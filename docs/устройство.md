# Как устроен виджет «Яндекс Погода»

Id: `pole.yandex-weather`. Живёт в `~/.config/omarchy/plugins/pole.yandex-weather/`
и переживает `omarchy update`, потому что это пользовательский плагин, а не
файл из `/usr/share/omarchy`.

## Части

| Файл | Что делает |
|------|------------|
| `BarWidget.qml` | Значок в баре: температура и иконка. Хранит последнее удачное чтение, раз в N минут ходит за новыми данными, строит и держит панель, пишет выбранный город в `shell.json`. |
| `Panel.qml` | Всплывающая панель: текущая погода, поиск города, список городов, прогноз на 10 дней и разбор по времени суток. Только рисует: данные и действия берёт у `BarWidget`. |
| `WeatherIcon.qml`, `WeatherIcons.js` | Значок погоды: контур по виду погоды (день/ночь), вставленный в `Text` как RichText, см. `icons/README.md`. |
| `WeatherData.js` | Чистые функции: температура «+8°», диапазон дня, выбор дневной/ближайшей сводки, «N минут назад». |
| `bin/yandex-weather.py` | Сеть и разбор HTML: `weather <slug>`, `search <запрос>` (по-русски и по-английски), `locate` (город по IP), `validate <ссылка>`. Печатает по одному JSON-объекту. |
| `i18n/ru.json`, `i18n/en.json` | Тексты панели. Русский берётся, когда в `~/.config/omarchy/language` стоит `ru`. |
| `icons/` | Превью контуров и лицензии Lucide и Fluent UI; сами контуры лежат в `WeatherIcons.js`. |

## Данные

Источник — те же страницы, что открывает браузер:

- `https://yandex.ru/pogoda/<slug>` — текущая погода (скрытая сводка
  «погода сейчас: …» и JSON `fact`) и 10-дневная полоска;
- `https://yandex.ru/pogoda/<slug>/details` — подробные карточки всех десяти
  дней по частям суток (утро, день, вечер, ночь: температура, осадки, ветер,
  влажность, ощущается).

Скрипт ходит в сеть сам, с таймаутом 20 секунд и потолком в 4 МБ на ответ.
Скрипт сводит подпись Яндекса к «виду» погоды (`clear`, `mostly`, `rain`,
`snow`, `sleet`, `thunder`, …) и признаку «ночь», а рядом всегда отдаёт саму
подпись. Ничего не выполняется из ответа: числа и короткие строки (до 80
символов) попадают в JSON, а QML рисует их только как `PlainText`.

Если карточки есть, а текущего значения нет (так бывает на странице
`/details`), скрипт один раз запрашивает главную страницу места.

## Сеть и обновление

- Раз в `refreshMinutes` минут (по умолчанию 30) — фоновый опрос страницы.
  С `refreshMinutes: 0` опрос выключен, и погода запрашивается только при
  открытии панели или по клику на стрелку.
- Неудачное обновление не стирает последнее удачное чтение: в панели
  появляется «не обновлено» и подпись внизу, в баре остаются старые цифры.
- Средняя кнопка на значке — обновить сейчас. Колесо над значком — следующий
  или предыдущий город из списка.

## Настройки (`shell.json > bar.layout[].…/pole.yandex-weather`)

```jsonc
{
  "id": "pole.yandex-weather",
  "city": "elektrougli",          // slug города на Яндекс.Погоде
  "cityName": "Электроугли",      // как город называется в панели
  "cities": [ ... ],              // короткий список для переключения
  "refreshMinutes": 30,           // 0 — только вручную
  "showCondition": false          // добавлять в бар слово «ясно», «дождь»…
}
```

Город меняется из панели (чипы, поиск, колесо): `BarWidget` сразу
записывает его через `updateEntryInline`, поэтому выбор переживает
перезапуск и виден на всех мониторах.

## Поиск и геолокация

- Поиск шлёт запрос в подсказки Яндекса в виде «<что ввели> погода» — так он
  отвечает и на английское название («Moscow»), и на русское («Москва»),
  и на сокращения («спб»).
- Кнопка «Определить» в панели: `ipinfo.io` даёт координаты по IP, страница
  Яндекса по этим координатам — сам город и его slug; город тут же
  становится текущим и попадает в список.

## Управление

| Действие | Мышь | Клавиатура в панели |
|----------|------|---------------------|
| Открыть панель | клик по значку | — |
| Обновить | средняя кнопка / стрелка у «Прогноз на 10 дней» | `r` |
| Следующий/предыдущий город | колесо | `n` / `p`, затем Enter |
| Выбрать день | клик по строке | ↑ ↓, ← → |
| Убрать город из списка | правый клик по чипу | — |
| Поиск города | поле «Найти город…» | `/` или `f`, затем Enter |
| Закрыть | клик мимо | `Esc` |

## Значения ошибок

`network`, `not-found`, `bad-slug`, `no-forecast`, `too-large`, `parse` —
у каждой есть строка в `i18n/<язык>.json` (`error.<код>`), поэтому панель
никогда не показывает сырой код.

## Как устроены значок и бар

Бар измеряет виджет по его `implicitWidth`, а не по тому, что тот нарисовал,
поэтому в баре нет отдельного кастомного значка:

- **Бар** — один текстовый элемент `BarIconButton`: глиф погоды из
  `WeatherIcons.glyphFor()` и температура, поднятые на 25 % относительно
  шрифта бара и соединённые в одну строку. Ширина всего ярлыка — то, что бар
  реально оставляет виджету, поэтому ничего не налезает на соседа.
- **Панель** — `WeatherIcon.qml`: вектор `Image` из `WeatherIcons.sourceFor()`,
  отрисованный с учётом масштаба экрана, поэтому линии не размываются.
- **Шрифт панели** увеличен целиком, в одном месте (`Panel.qml`, функция
  `text()` над токенами `Style.font.*`): подписи, дни, разбор по частям
  суток и иконки растут вместе.

## Проверка без интерфейса

```bash
python3 ~/.config/omarchy/plugins/pole.yandex-weather/bin/yandex-weather.py weather elektrougli | python3 -m json.tool | head -40
python3 ~/.config/omarchy/plugins/pole.yandex-weather/bin/yandex-weather.py search "Электроугли"
```

Вернуть значок Яндекса вместо стандартного: `omarchy bar put pole.yandex-weather
--section centerEnd`.
